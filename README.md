# 🛠️ 图片工具插件 (anr_plugin_image_tools)

[Auto-NovelAI-Refactor](https://github.com/zhulinyv/Auto-NovelAI-Refactor) 的图片处理插件: 把常用的本地图片操作集中到一个面板里 —— 变换、压缩转换、色彩与画质、拼合与动图、水印与边框、批量整理、元数据读写清除、LSB 隐写。

全部功能**只用 Pillow / NumPy 实现, 不引入新依赖、不加载模型**, 纯本地 CPU 运算。

## ✨ 功能特性

| 面板 | 能力 |
| --- | --- |
| 🖼️ 变换 | 裁剪 (自由尺寸 / **定比例 1:1、4:5、16:9 等 11 种** / 百分比 / 九宫格定位)、**自动裁边** (按边角取样或白/黑/透明收缩空白边)、旋转 (90°/180°/任意角度, 可扩展画布)、镜像翻转 (水平/垂直/两者)、放大缩小 (按倍数 / 最长边 / 指定尺寸, 保持宽高比、仅缩小不放大)、**扩展画布** (按比例或指定尺寸补边, 透明 / 自定义底色)、可换输出格式 |
| 🗜️ 压缩转换 | 输出 png / jpg / webp / avif / tiff / bmp、质量与 PNG 压缩级别、**按目标体积自动压** (二分质量)、限制最长边、透明底色选择、**顺带生成缩略图** (指定长边与格式, 存到 `thumbs/`) |
| 🎨 调色 | **自动校正** (自动对比度 / 直方图均衡 / 自动白平衡, 可叠加)、**色彩调整** (亮度 / 对比度 / 饱和度 / 色相 / 锐度 / 伽马)、**一键滤镜** (灰度 / 反色 / 复古 / 冷 / 暖 / 高对比 / 柔和 / 褪色)、**模糊 / 锐化 / 降噪** (高斯模糊 / 方框模糊 / USM 锐化 / 中值降噪 / 高斯降噪) |
| 🧩 拼合 | **拼图** (网格拼合, 可选列数、单格尺寸、适配方式、间距 / 背景 / 边框色)、**长图拼接** (横向 / 纵向, 对齐方式)、**分割大图** (按行列数或单块尺寸切分) |
| 🎞️ 动图 | **动图合成** (多帧 → GIF / WebP 动图, 可调帧时长、循环次数、**乒乓回放**) |
| 🎀 装饰 | **文字水印** (支持 `{name}` `{index}` `{seed}` `{width}` `{height}` 占位符, 可平铺 / 九宫格 + 边距 / 旋转 / 透明度 / 描边)、**图片水印** (透明 PNG, 可缩放旋转、可平铺)、**边框装饰** (纯色描边 / 圆角 / 阴影 / 拍立得 / 圆形头像) |
| 🗃️ 整理 | **图片查重** (dHash 感知哈希 + 汉明距离聚类, 输出 CSV, 可选把重复项移动到子目录)、**质量筛查** (按分辨率 / 文件体积 / 边缘清晰度挑出可疑的模糊或过小图片)、**批量重命名** (模板化命名, 支持序号补零, 先预览再落盘)、**生成参数清单** (把每张图的 prompt / seed / steps 等汇总成 CSV) |
| 🔍 读取元数据 | 一次性读取全部: PNG 文本块 / NovelAI 隐写数据 / 自定义隐写载荷 (可带密码解密) / EXIF 全标签 / ICC / XMP / 生成参数摘要 (不修改图片) |
| 🏷️ 写入数据 | 写元数据 (任意键值, 已知键名同时写进 EXIF); 打开「写入隐写」开关后改把文本/文件藏进像素最低位 (可选密码与压缩, 统一转存 PNG); **参数搬运**: 从参考图整份搬或只搬指定字段 (如只搬 seed) |
| 🧹 清除元数据 | 按类别勾选清除 (文本块 / 隐写 / EXIF / ICC / XMP), 可只清除指定键, 清除后写自定义信息 |

所有动作都支持**单张图片或整个目录批处理**, 执行期间可随时点「⏹ 停止」。

## 📦 依赖

- Piexif (项目本身已在使用; EXIF 写入 / 清除)
- Pillow / NumPy (项目依赖)

## 🚀 使用方法

1. 把 `anr_plugin_image_tools` 目录放进 `Auto-NovelAI-Refactor/plugins/` (或在插件商店安装)
2. 重启后端 (插件在启动时加载)
3. 侧边栏会出现「🛠️ 图片工具」, 10 个子页签对应: 变换 / 压缩转换 / 调色 / 拼合 / 动图 / 装饰 / 整理 / 读取元数据 / 写入数据 / 清除元数据

## 🔗 处理顺序

多个功能同时开启时按固定顺序串行, 不用自己操心先后:

- **变换**: EXIF 方向纠正 → 裁剪 → 自动裁边 → 调整长宽 → 旋转 → 翻转 → 缩放 → 扩展画布
- **色彩与画质**: 自动校正 → 色彩调整 → 滤镜 → 模糊 / 锐化 / 降噪
- **水印与边框**: 先加边框 → 再打水印 (保证水印落在最终画布上, 不被边框盖住)

## 🏷️ 元数据与隐写说明

「元数据」与「LSB 隐写」是同一件事的两面 (都是"图片里藏的信息"), 因此合并在一个面板:

- **读取**: 一个按钮给出全部 —— 文件信息、PNG 文本块、NovelAI 隐写数据 (`stealth_pngcomp`)、
  本插件写入的隐写载荷、EXIF 全标签、ICC / XMP, 并自动摘要出 prompt / seed / steps 等生成参数。
  加密的隐写载荷在「隐写密码」里填上密码即可解密; 读到的载荷会导出到 `outputs/lsb_extract/` (二进制内容不会被截断)。

- **写入元数据**: 「写入内容」支持 JSON 对象或每行一个 `键=值`, 键值会写进 PNG 文本块;
  键名是 `ImageDescription` / `Artist` / `Copyright` / `Software` / `DateTime` / `UserComment` 等已知名称时,
  会**同时写进 EXIF** (png / jpg / webp / avif / tiff)。
  写入 `Comment` 键 (值为 NAI 参数 JSON) 后, 自带的法术解析可以重新读到生成参数。

  ```
  Title=我的作品
  Artist=zhuli
  ```
  或
  ```json
  {"Title": "我的作品", "Artist": "zhuli", "Comment": {"prompt": "1girl", "seed": 42}}
  ```

- **写入隐写数据**: 见下面的格式说明。

- **清除更彻底**: 「清除项」按类别勾选 —— PNG 文本块 (tEXt/iTXt/zTXt)、NovelAI 隐写数据、自定义隐写数据、
  EXIF、ICC 色彩配置、XMP; 「仅清除指定键」可以做到"只删 Comment, 其余保留";
  清除后还能写入一条自定义信息 (`Auto-NovelAI-Refactor` 字段)。

## 🖊️ LSB 隐写格式

自研格式 `ANRLSB1` (与 NovelAI 的 `stealth_pngcomp` 互不干扰):

```
魔数 "ANRLSB1\0" (8B) + 标志 (1B) + 通道 (1B) + 载荷长度 (4B, 大端) + 盐 (16B) + HMAC-SHA256 (32B) + 载荷
标志位: bit0 = 已加密, bit1 = 已压缩 (zlib)
```

- 载荷按位写入指定通道的**最低位** (每像素只改 1 个最低位, 肉眼不可见), 行优先扫描
- **默认写入 R 通道**: NovelAI 的隐写占用 Alpha 通道, 避开可避免互相覆盖; 读取时自动尝试 A/R/G/B, 无需记住参数
- 可选密码: PBKDF2-HMAC-SHA256 派生密钥 → SHA-256 计数器流加密 → HMAC-SHA256 完整性校验
  (只依赖标准库, 属隐写混淆用途, 不等同于专业加密工具; 只保护内容, 不隐藏"有隐写数据"这一事实)
- 容量 ≈ 宽 × 高 ÷ 8 字节 (832×1216 约 123 KB, 超出会明确提示)
- 输出统一转存 **PNG**: 重新压缩 / 裁剪 / 缩放会破坏 LSB 数据

## ⚠️ 注意事项

- 裁剪 / 旋转 / 缩放会破坏图片里的 LSB 隐写数据, 变换面板会在结果里给出提示
- 默认**不覆盖原图**, 输出为 `原名 + 后缀`, 也可指定输出目录或显式勾选「覆盖原图」
- 面板内的选项字段使用 `type="radio"` 而不是 `type="select"`: 前端 `ui.js` 的 `el()` 会把
  `selected=false` 也写成 `selected="false"` (属性存在即生效), 导致所有 option 都被标记选中、
  下拉框停在最后一项; radio 走 CSS class 判断, 不受该问题影响
- 跨面板字段 id 带前缀 (`tf_` 变换 / `cv_` 压缩转换 / `co_` 调色 / `cg_` 拼合 / `an_` 动图 / `dw_` 装饰 / `og_` 整理 / `rd_` 读取 / `mw_` 写入 / `cl_` 清除):
  前端按 id 从全局注册表取值, 重名会串值
- **字段加好了但忘了写进动作的 `inputs`**, 前端就不会把值发过来 —— 后端只会看到默认值, 功能静默失效。
  后端 `strip_prefix(v, "tf_")` 拿到的是裸键名; 新增字段时务必同步补 `inputs` (有回归脚本检查这一条)
- emoji 约定: 动作标签**最多带一个** emoji —— 前端只在标签不带 emoji 时才补统一前缀
  (按钮补 `▶️ `、输出区标题补 `📤 `), 自带则原样使用; 标签里写成两个连用
  (如 `"🗜️📂 压缩并整理"`) 会原封不动显示出来; 面板 / 插件图标与报告里的分隔 emoji 只选
  `web/assets/emoji/72x72/` 里有本地 SVG 的 (前端 Twemoji 统一化靠它, 缺资源会回退成系统原生 emoji)

## 🧭 界面排版约定 (改面板前必读)

- **左列分区**: 用 `Field(type="section")` 把同类功能的参数划分成区域 (输入 / 各功能 / 输出),
  分区标题由前端渲染成带竖线与下边框的标题, 中间的 `description` 作分区说明。
  不要靠"参数挨在一起"来表达分组 —— 参数一多就分不清哪个属于哪个功能。
- **每个功能分区先给开关**: 分区里第一个字段是该功能的 radio 开关 (不裁剪 / 不调整 / 不旋转 / 不翻转 / 不缩放 / 不裁边 / 不扩展 …),
  其余参数用 `show_if` 挂在开关上, 选「不X」时整组收起。开关是**权威** —— 后端也按开关判断
  (例如 `img_ops.crop_enabled` / `trim_enabled` / `pad_enabled`), 不能只看宽高是否为 0,
  否则面板上明明关掉了、却会被记住的历史值处理掉。
- **参数并排, 一行放两个 (核心排版规则)**: 一个参数占一整行、下一个参数再另起一行是最难看的排法。
  给语义上成对的字段加**相同的** `row_group` 值, 前端就把它们渲染进同一个 `.field-row` (flex, 各占 `flex:1`)
  —— 例: 亮度 + 对比度、水印透明度 + 缩放、旋转角度 + 扩展画布、质量 + 保留元数据。
  现在 10 个面板共 **199 个左列字段由约 199 行压到 130 行**, 实测标签零溢出。
  规则:
  - `row_group` 只在**相邻**字段间生效; 同组字段必须在字段列表里紧挨着
  - **宽控件不能并排**: `textarea` / `path` / `image` / `filearea` 必须独占整行, 塞进 `.field-row` 会被压扁
    (校验脚本 `imgtools_layout_check.py` 里以 `WIDE_ONLY` 集合守住这条)
  - `section` 分区标题也不能进行
  - **互斥字段可以共用一行**: 两个 `show_if` 互斥的字段填同一个 `row_group`, 同一时刻只显示一个,
    自动占满整行 —— 例: 裁剪的「九宫格定位」与「自定义 X/Y」、水印的「九宫格定位 + 边距」与「平铺间距」、
    边框的「描边色」与「底部留白」。这样一行能覆盖两套互斥的参数, 不必各占一行
  - 长解释**移到 `placeholder`**: 原来靠长标签承载的说明 (「不覆盖原图时使用」「0 = 不限」) 改写成占位文本,
    标签就能缩短到能和别的字段并排
  - 每个面板**至少保留一个独占整行的字段** (通常是最长的那条), 避免整列全是双列、失去视觉锚点
- **整行被隐藏时前端自动收起该行**, 不会留下空行间距 (所以整组 `show_if` 关掉时并排行会整个消失)
- **右列顺序**: 动作的输出框 (`Action.show_output`, 内含图片画廊 / 汇总 / 逐项明细 / 打开保存目录按钮)
  排在最上, 说明类字段用 `column="right_bottom"` 排在输出区**下方**。
- **出图动作绝不能用 `set_field` 把结果写进 textarea**: 那样前端不会创建输出框, 结果里的图片就完全
  不显示了 (只有像「读取元数据」这种纯文本面板才用 textarea + `set_field` 承载结果)。
- **展示结果的文本框要设 `readonly=True`**: 结果框是给人看 / 复制用的, 不该被随手改掉
  (「读取元数据」的 `rd_out` 就是这么配的)。只读只拦用户 —— 动作的 `set_field` 走 JS 赋值,
  值还原、还原默认参数也照常写入。前端 `ui.js` 用 `input.readOnly = true` **属性**赋值,
  不能靠 `setAttribute("readonly", false)` (该属性"存在即生效", 同 `selected=false` 的老坑);
  同时加 `.readonly` 类, 由 `app.css` 给一个"沉底底色 + 虚线描边 + 默认光标"的只读外观。
  ⚠ 只读样式**必须写在 `app.css` 里 `body.has-custom-bg input/textarea` 那条统一底色之后**
  (并连 `body.has-custom-bg ...` 变体一起写): 否则用户设了自定义背景时, 那条规则会把只读底色盖掉,
  只读框看起来和普通输入框一模一样 (实测就是这个坑 —— 放在 `base.css` 里被盖了)。
  注: 法术解析 (pnginfo) 那几个文本框早就只读 (走 `el()` 的 `readonly` 属性), 未加该类, 外观不变。
- 逐条明细 (`build_result` 返回的 `text`) 由前端输出框内的明细区展示, 汇总 (`message`) 显示在提示条上。
